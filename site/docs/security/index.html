Security and privacy

Dewline needs no account, sends no telemetry, and goes on the network only for a feature you can see.

No account, no telemetry

You never sign up or sign in. The code has no analytics, no usage reporting and no crash reporter. The app's logs go to the macOS unified log on your Mac and nowhere else. Sparkle's system profile is off, so an update check sends no hardware details.

What goes over the network

The app makes four kinds of request. Nothing else in the code opens a connection.

Updates
Once a day, once the first-run line about updates has shown, and whenever you choose Check Now. The app asks dewline.arkwerx.com/appcast.xml for the feed and downloads an update from GitHub. Each request carries the user agent Dewline. Turn off the daily check in Settings > General > Updates. Debug and unsigned builds never contact the feed.
Fonts
Only when you install a font from the catalog in Settings > Fonts. Each file comes from raw.githubusercontent.com, google/fonts at one pinned commit, in an ephemeral session with no cookies and no cache. The file is pinned by URL, byte size and SHA-256, and a download that does not match is refused before it touches the disk.
Collaboration
Only while you share a file or join one. Edits and cursors go to the other Mac directly, or through n0's relay, use1-1.relay.n0.iroh.link, when no direct path opens. The relay sees node ids, addresses and timing. The content is encrypted end to end.
Link previews
When a note shows a web link, Dewline asks that site for the page's title, icon and picture, as Messages does. It asks only for links on screen, only for http and https addresses, and never for addresses on your own network. The site sees your IP address and a request like a browser's. Previews are kept for 7 days in ~/Library/Caches/dev.arkwerx.dewline/LinkPreviews. Turn them off in Settings > Editor > Link previews, which also deletes the saved ones.

Images in a note load from relative paths on disk only; an image given as a URL is never fetched. Links you click open in your browser.

The agent panel

The panel starts the agent program you chose, on your Mac. Dewline sends it what you type and the note you attach, and lets it read and write files only inside the open folder. Where the agent sends your text is up to that agent.

What stays on disk

Snapshots
~/Library/Application Support/dev.arkwerx.dewline/snapshots/. Folders are 0700 and files 0600. Each version is compressed with zstd, not encrypted. Files and saves says how long each one is kept.
Decisions log
decisions.jsonl in the snapshots folder: one line for each agent change you kept or reverted.
Control socket
~/Library/Application Support/dev.arkwerx.dewline/run/control.sock, in a 0700 folder, itself 0600. The app removes it when it quits.
Collaboration keys
Your login Keychain, service dev.arkwerx.dewline.sync: this Mac's node key and each share's document key. They are readable only while the Mac is unlocked and never sync to another device.
Inbox
~/Documents/Dewline/Inbox.md, unless you choose another file. Every capture appends to it.
Shared copies
~/Documents/Dewline Shared/, unless you choose another folder. A guest's copy of a shared file goes here, and a file already there is never overwritten.

Files that may hold secrets are never snapshotted: any .jsonl file (agent transcripts), .claude.json, and anything in a file-history folder. Neither are .json or .toml files in a .claude or .codex folder.

Caution

The collaboration keys sit in the login Keychain, so any app you allow to read them can (0009). The data-protection Keychain needs an entitlement and a provisioning profile that this build does not have yet.

Threats and controls

Each row names a control in the code and where it lives.

ThreatControl
Hostile Markdown in the editorNo JavaScript in a note runs anywhere. Mermaid and math render natively, off the main thread, capped at 50 KB of source, a 250 ms render and a 16 megapixel picture. A failed render shows the source. The parser and the merge are fuzzed. Highlighting skips lines over 16 KB or with over 2,000 scope changes. (core/crates/ffi, core/fuzz)
Hostile Markdown in an exportRaw HTML in the source is written as text. A javascript: link loses its target. The page carries a Content Security Policy that allows no script. PDF layout runs in a web view with page scripts off, no stored data and no navigation past the first page. (core::export, Export.swift)
Images that reach outside the folderAn export inlines an image only from inside the document's folder, through the path jail, up to 20 MB, and only when its bytes are PNG, JPEG, GIF, WebP or SVG. (core::export)
A hostile page behind a linkPreviews ask only http and https addresses with a public host. They never ask localhost, .local names, or loopback, private or link-local addresses. The page loads in a LinkPresentation system process, not in the app, and its title and pictures are drawn as one image. LinkPresentation follows a site's redirects, which Dewline does not check. (LinkPreviews.swift)
A Finder preview of a hostile fileQuick Look runs as a sandboxed extension and returns static HTML with no script and no network access. Diagrams and math show as source, and no image is inlined. (app/QuickLook)
Path traversal and symlink swapsOne jail resolves a path with realpath, opens it from the root's descriptor with O_NOFOLLOW_ANY, and checks the opened file is still inside. A property test checks mixes of dots, links and loops. (core::jail)
An agent over MCPstdio only, no network listener. The server refuses a root that is your home folder or above it, inside ~/Library, or holding .ssh. It serves only .md, .markdown and .txt files outside dot folders, within the size and count limits on the MCP server page. Its one write appends to the inbox. (cli/src/mcp.rs)
Another process on the control socketThe socket sits in a folder only you can enter, and both ends check that the peer runs as your user. A request is one line of at most 16 KB, sent within 2 s, with at most 16 connections. An open request must name an absolute path to an existing regular file. Nothing that arrives writes a file: a hook's claim carries ids, a path and BLAKE3 hashes, never content, and can only label a change. (ControlSocket.swift, cli/src/control.rs)
A crafted dewline:// linkEvery path goes through the jail: inside your home folder, never in ~/Library or a .ssh folder. An export link writes only a file named for its format. (SchemeLinks.swift)
A tampered updateThe feed and each archive are signed with EdDSA, and Sparkle checks the archive before it extracts it. Releases are signed with the ArkWerx Developer ID and notarized. Release notes render with JavaScript off. (app/project.yml, Updates.swift)
A stolen invite or a hostile collaboratorAn invite admits one join attempt, and the host approves each one by name. Edits are sealed under the document key and signed by a member's node key; anything else is dropped. Removing someone rotates the key. A guest's Mac takes only a file name from the host, reduced to a bare name in the shared folder. (core/crates/sync, 0009)
A writer racing your saveSaves are compare-and-swap against the bytes you last absorbed. A refused save writes your text to the file's draft snapshot, never over the newer file. (core::file, core::engine)

The controls at work

The MCP server's roots

Each refusal exits with status 1 before the server reads anything:

$ cd ~
$ dewline mcp .
dewline: .: the folder is your home folder or holds it
$ dewline mcp Library/Notes
dewline: Library/Notes: the folder is inside ~/Library
$ dewline mcp server
dewline: server: the folder holds .ssh

Inside a served folder, a read that leaves the folder, follows a symlink out of it, or reaches into a dot folder returns an error result. Here alias.md is a symlink to a file one folder up:

{"jsonrpc":"2.0","id":2,"result":{"content":[{"type":"text","text":"../secret.md: it is outside the folder"}],"isError":true}}
{"jsonrpc":"2.0","id":3,"result":{"content":[{"type":"text","text":"alias.md: it is outside the folder"}],"isError":true}}
{"jsonrpc":"2.0","id":4,"result":{"content":[{"type":"text","text":".git/config.md: only .md, .markdown and .txt files outside dot folders are served"}],"isError":true}}

Exporting a hostile note

A note with a script tag, an image with an onerror handler and a javascript: link:

# Hostile

<script>alert(1)</script>

Text <img src=x onerror=alert(2)> here.

[a link](javascript:alert(3))
$ dewline export hostile.md --to html -o hostile.html

The page's policy and body, as written:

<meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline'; img-src 'self' data:">
…
<h1>Hostile</h1>
<pre class="html">&lt;script&gt;alert(1)&lt;/script&gt;
</pre>
<p>Text &lt;img src=x onerror=alert(2)&gt; here.</p>
<p><a>a link</a></p>

Reporting a vulnerability

Report it privately through GitHub: open the repository's Security tab and choose Report a vulnerability. Do not open a public issue or pull request for it.

  • Include the Dewline version (Dewline > About Dewline), the macOS version, and the steps or a file that reproduce the problem.
  • Disclosure is coordinated over 90 days from the report. The fix ships and the advisory publishes within that window, sooner when the fix is ready. If 90 days pass without a fix, you are free to publish.
  • Reporters are credited by handle in the advisory and the release notes when they agree.
  • Only the latest release gets fixes. A security fix ships as a critical update through the signed feed, so the app shows it at once. It never restarts on its own.
