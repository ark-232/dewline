Agents

Dewline marks each change another writer makes to an open note, so you can keep or revert it. You can also chat with your own coding agent beside the note.

Keep or revert a change

When git, a sync app, a script or an agent writes to an open note, Dewline marks the change. A bar under the text names the writer: “Claude changed 3 places · 2 other notes”.

  1. Step through the changes with the bar's arrows, or ⌃⌘↓ and ⌃⌘↑.
  2. Keep or revert the one in focus.
  3. Click “2 other notes” for the Changes list (⇧⌘R), which includes notes changed while closed.
CommandKeys

Revert Change⌥⌘⌫
Keep All Changes⇧⌘↩
Revert All Changes⌥⇧⌘⌫

Each choice is one edit you can undo. A revert leaves the other app's history alone.

Chat with your agent

The Agent panel talks to a coding agent you install yourself. Dewline ships no model and needs no account.

  1. Press ⌥⌘A, or click Agent in the toolbar. The panel opens beside the note.
  2. Pick an agent from the menu at the top.
  3. Type and press ↩. The open note and any selection go along.
  4. Keep or revert its edits, which arrive marked.

⌘. stops a turn. The agent works only inside the open folder and asks before it runs a command.

Run each agent once in Terminal to sign in. Settings > Agents > Add Agent… adds any other Agent Client Protocol agent.

Mark edits from other agents

An agent you run in Terminal writes files itself. Hooks let its edits carry its name.

  1. Click Set Up on the status bar line “Agent edits aren't marked yet”, or in Settings > Agents.
  2. Confirm the files it changes. Each keeps a backup beside it.
  3. For Codex, trust the hooks: open /hooks in Codex, select each Dewline hook and press t.

In Terminal, dewline doctor --install-hooks does the same.

Let agents see what you reverted

Dewline logs each Keep or Revert of an agent's change, without the text. Agents read the log with dewline changes or the MCP decisions tool. Add this to a project's instructions:

Before you edit notes here, run `dewline changes --json --since <today>`
and don't redo a change the user reverted.

How Dewline knows who wrote it

A change carries an agent's name only when its hooks prove the write was theirs. Panel edits need no hooks.

The four steps, and the lines one Edit sent
  1. Before a tool runs, its PreToolUse hook sends the file's realpath and a BLAKE3 hash of its bytes. It also sends declared, the hash of the bytes the change will make.
  2. The tool writes the file.
  3. After it runs, its PostToolUse hook sends the hash of the bytes it finds.
  4. Dewline names the agent when one session's calls chain from the old bytes to the new. Each declared hash must match, and the change must land within 5 seconds.

The declared hash keeps a second writer from taking the agent's name. If something else wrote during the call, the bytes on disk would not match it.

Claude Code changed Ship 0.1.0 to Ship 0.1.0 on Friday, then ended the turn. The PreToolUse declared hash is the PostToolUse hash.

What shows as another app
  • Edits through a shell: Claude Code's Bash tool, Codex's shell, Cursor's terminal, codex exec, and any edit that skips the hooks.
  • A call whose result Dewline can't compute exactly. That includes an Edit of a file with CR or CRLF line endings, or of a file that isn't plain UTF-8. It also includes a Codex patch that would stop partway. A file over 64 MB gets no declared hash.
  • Sync apps, scripts and every other app.

Note

In its auto and bypassPermissions modes, Claude Code edits with sed, heredocs or short scripts. Many of those edits show as from another app.

Autosave waits for the agent
  • A Claude Code tool call on a note holds that note's autosave until the turn ends: Stop, StopFailure or the next UserPromptSubmit. Your edits stay in the window.
  • A file Claude Code loads as instructions, such as CLAUDE.md, is held until the session ends.
  • Every hold lapses 30 minutes after the session's last hook event.
  • Codex patches hold nothing. While any hooked call on a file is open, Dewline waits up to 10 seconds before it lands an outside change there.
What a hook sends

Each hook runs dewline notify with the event's JSON on stdin. It sends one line per file on the app's control socket: the event, agent, session, tool, call id, realpath and BLAKE3 hashes. It never sends file content.

  • It never writes a file, starts Dewline or runs another program.
  • When Dewline isn't running, it stops before reading stdin or any file.
  • It reads at most 64 MB of stdin and hashes Write's content as it streams.
  • It finishes within 2 seconds and always exits 0, so it can't block a tool call.
  • Session and call ids are 1 to 128 printable ASCII characters. Dewline refuses any other line.
Install the hooks by hand

Merge these entries into each agent's settings. Claude Code also reads a project's .claude/settings.json.

{
  "hooks": {
    "PreToolUse": [{"matcher": "Read|Edit|MultiEdit|Write", "hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook claude"}]}],
    "PostToolUse": [{"matcher": "Read|Edit|MultiEdit|Write", "hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook claude"}]}],
    "Stop": [{"hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook claude"}]}],
    "StopFailure": [{"hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook claude"}]}],
    "UserPromptSubmit": [{"hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook claude"}]}],
    "SessionEnd": [{"hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook claude"}]}],

Remove the hooks

Delete each hook whose command ends in notify --hook claude, codex or cursor. Or copy back the .dewline-backup-<seconds> file beside each settings file. Without hooks, agent edits show as from another app and autosave never waits.
