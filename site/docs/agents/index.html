Agents and changes

When a coding agent changes a file you have open, Dewline marks the change and puts the agent's name on it, but only when the agent's hooks prove the write was theirs. This page covers that proof, what stays Unknown, how Dewline holds your autosave while an agent works, and how to install the hooks.

How a change gets a name

Dewline names an agent only when two things hold. The agent's hooks bracket the write with one tool call id. And the change that call declared (Write's content, Edit's strings, Codex's patch) turns the file's previous bytes into the bytes now on disk. Anything else is Unknown.

  1. Before the tool runs, its PreToolUse hook sends the file's realpath, a BLAKE3 hash of its bytes, and declared: the hash of the bytes the declared change will make.
  2. The tool writes the file.
  3. After it runs, its PostToolUse hook sends the hash of the bytes it finds.
  4. Dewline sees the change land. It names the agent when one session's calls chain from the old bytes to the new, each call's declared hash matches what its PostToolUse found, and the change came within 5 seconds of the calls. When no session's calls link the two, or more than one session's do, the change stays Unknown.

The declared change is what keeps a second writer from taking the agent's name. If something else wrote to the file during the call, the bytes on disk wouldn't match the declared hash. Hashes before and after the call alone would credit the agent with both writes.

Cursor's tool hooks carry conversation_id and tool_use_id, but as of 30 October 2026 Cursor documents no tool_input fields for its Write tool, the one its edits run as. Without them, nothing can declare what an edit wrote.

What stays Unknown

An Unknown change shows with a hollow bead and a dashed underline, and you keep or revert it like any other. These show as Unknown:

  • Edits through a shell: Claude Code's Bash tool, Codex's shell, Cursor's terminal, codex exec runs, and any edit that skips the hooks. A hook around a command can't say which bytes the command wrote.
  • A call whose result Dewline can't compute exactly: an Edit of a file with CR or CRLF line endings, a file that isn't UTF-8 text, holds a NUL byte or starts with a byte-order mark, an Edit Claude Code would refuse, or a Codex patch that would stop partway. A file over 64 MB gets no declared hash.
  • Sync apps, scripts and other apps.

Note

In its auto and bypassPermissions modes, Claude Code tells the model to edit with sed, heredocs or short scripts, so many of its edits there show as Unknown.

Autosave holds

While an agent works on a file, Dewline holds the file's autosave, so your save and the agent's write don't cross. Your edits stay in the window, and the autosave runs once the hold ends.

  • A Claude Code tool call on a file (Read, Edit, MultiEdit or Write) holds its autosave until the session's turn ends: Stop, StopFailure, or the next UserPromptSubmit.
  • A file Claude Code loads as instructions, such as a CLAUDE.md, is held until the session ends.
  • Every hold lapses 30 minutes after the session's last hook event, so a crashed session can't hold a file for good.
  • Codex patches put no hold on autosave. Codex truncates a file and then writes it, so while any hooked call on a file is open, Dewline waits up to 10 seconds before it lands an outside change on that file.

Keep or revert

An agent's change is marked in its writer's color. Pick the hue for each writer in Settings > Agents > Writers. You keep or revert it like any marked change, with the commands and keys in Files and saves. Each decision is one undoable edit, and each one is logged as the next section describes.

The decisions loop

Each time you keep or revert an agent's change, Dewline appends one line to ~/Library/Application Support/dev.arkwerx.dewline/snapshots/decisions.jsonl, a file only you can read. The line holds the agent, its session, the file, the UTC time, kept or reverted, and a BLAKE3 hash of the change's text. The text itself is never logged.

Agents read the log back before their next edit, through dewline changes or the MCP server's decisions tool. A line in a project's instructions file closes the loop:

Before you edit notes here, run `dewline changes --json --since <today>`
and don't redo a change the user reverted.

Agent transcripts and settings files are private to Dewline: never snapshotted, and their decisions never logged. Security and privacy lists which files those are.

Install the hooks

Run this in Terminal. Settings > Agents shows the same command with a Copy Command button, and shows each agent as Installed or Not installed.

$ dewline doctor --install-hooks

It shows the hooks it would add to each agent's settings and asks before it writes, keeping a backup; dewline doctor has the details. Each hook runs the dewline you ran, by absolute path. Run dewline doctor afterward to check.

Codex

Codex runs a new or changed hook only after you trust it. Start Codex, open /hooks, select each Dewline hook and press t.

By hand

These are the entries --install-hooks adds, with the command inside the app. Merge them into your settings. Claude Code also reads a project's .claude/settings.json.

{
  "hooks": {
    "PreToolUse": [{"matcher": "Read|Edit|MultiEdit|Write", "hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook claude"}]}],
    "PostToolUse": [{"matcher": "Read|Edit|MultiEdit|Write", "hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook claude"}]}],
    "Stop": [{"hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook claude"}]}],
    "StopFailure": [{"hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook claude"}]}],
    "UserPromptSubmit": [{"hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook claude"}]}],
    "SessionEnd": [{"hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook claude"}]}],
    "InstructionsLoaded": [{"hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook claude"}]}]
  }
}
{
  "hooks": {
    "PreToolUse": [{"matcher": "^apply_patch$", "hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook codex"}]}],
    "PostToolUse": [{"matcher": "^apply_patch$", "hooks": [{"type": "command", "command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook codex"}]}]
  }
}

  "hooks": {
    "preToolUse": [{"command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook cursor"}],
    "postToolUse": [{"command": "/Applications/Dewline.app/Contents/Helpers/dewline notify --hook cursor"}],

Remove them

Delete each hook whose command ends in notify --hook claude, notify --hook codex or notify --hook cursor from the files above, or copy back the .dewline-backup-<seconds> file that --install-hooks left beside each one. dewline doctor then lists those events as missing. Without hooks, agent changes show as Unknown and Dewline puts no hold on your autosave.

What a hook sends

Each hook runs dewline notify with the event's JSON on stdin. It sends Dewline one line per file on the app's control socket, as in the example above: the event, the agent and session, the tool and its call id, the file's realpath, and BLAKE3 hashes. Never the file's content.

  • It never writes a file, never starts Dewline and never runs another program.
  • When Dewline isn't running, it stops before reading stdin or any file.
  • It reads at most 64 MB of stdin. Write's content is hashed as it streams and then dropped.
  • It finishes within 2 seconds and always exits 0, so it can't hold up or refuse a tool call.
  • Session and call ids are 1 to 128 printable ASCII characters. Dewline refuses a line that breaks any rule.
