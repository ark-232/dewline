Performance

Every number on this page comes from one run of scripts/perf.sh for 0.1.0, kept in perf/0.1.0.json. A release tag ships only when a run like it holds every budget.

Note

perf.sh does not record whether the Mac ran on battery or on power, so the run does not say.

A megabyte here is 1,048,576 bytes, as budgets.jq counts it. Open 10 MB is faster than Open 1 MB because the 1 MB open is the process’s first text draw, which waits while Core Animation sets up Metal.

What each budget measures

Keystroke
The editor opens the document, puts the caret inside a styled span in the middle, and types a and then Delete, 150 times each: 300 samples. Each sample runs from the key down through layout, display and the Core Animation commit.
Cold launch
A fresh copy of the app and the 1 MB document, both copied past the file cache with ditto --nocache, launched three times. The time runs from process start to the document window’s first display.
Warm launch
The built app opens the 1 MB document once unrecorded, then five more times. The median counts.
Open
Setting the text and drawing the first screen. Styling the rest of the document continues after it.
Idle
The app opens the document and waits until its CPU time holds for 2 s, then 10 s more. top then reads the memory footprint, and over the next 60 s the CPU, idle wakeups and context switches.
DMG
The universal app from scripts/build-release.sh, packed as a ULMO disk image the way scripts/sign.sh packs it.

How perf.sh runs

The plan times a keystroke in the app being typed in, so perf.sh brings the app to the front for the tests, the keystrokes and idle. A run in which the app was not in front refuses to write a result. You start it from a terminal in front and leave the Mac alone until it ends.

The keystroke parts run three times. Right after each keystroke a fixed integer workload measures the clock. A run whose clock reads 1.5 times the fastest run’s, or whose probe landed on an efficiency core for more than 1 keystroke in 100, runs again, for up to three rounds. This run needed no reruns.

# measures this Mac; writes perf/<version>.json with each budget’s result
$ scripts/perf.sh

To judge a result against the current ceilings without measuring again, run the gate the release workflow runs:

$ scripts/perf-gate.sh perf/0.1.0.json v0.1.0
perf-gate.sh: perf/0.1.0.json holds every budget

Note

perf/0.1.0.json still carries the budgets as they stood when the run wrote it, before record 0010, so its own pass field reads false. perf-gate.sh judges the file again against perf/budgets.jq, and that is the verdict a tag gets.

The four reset budgets

Four of the plan’s budgets were set before anything was measured. Three perf passes brought the other ten under budget. These four sit at what macOS and TextKit allow on this Mac, and the owner reset them after the third pass (0010). Each new ceiling sits slightly above that run, so a regression still fails.

BudgetWasNowWhy
Keystroke, 1 MB, p508 ms9.5 msDewline’s own code is about 0.5 ms of a keystroke. The rest is TextKit 2 layout, the Core Animation commit and AppKit’s software glyph drawing into 64-bit pixels.
Cold launch300 ms750 msA near-empty AppKit app that opens a file takes about 315 ms cold here. A new copy’s first launch costs about 10 ms per MB of bundle, and the Rust library is 16.5 MB per architecture.
Warm launch150 ms425 msThe same near-empty app takes about 240 ms warm. Dewline adds about 100 ms, in pieces of 3 to 13 ms.
Open 1 MB50 ms85 msThe first text draw in a process blocks 10 to 30 ms while Core Animation sets up Metal, and this open is that first draw.

The record reopens if the Rust library loses a large dependency (Mermaid, Loro or the sync stack), if TextKit or AppKit changes the keystroke path, or if a pass finds a piece of launch worth more than 20 ms.

Where a keystroke goes

A second test stamps each part of a keystroke, so each part’s own time counts toward one row and the rows add up to the frame. Parse, attributes and reveal are Dewline’s code: 0.49 ms together at the median. Everything else belongs to AppKit, TextKit 2 and Core Animation.
