Reference

Command line

The dewline command opens files from a terminal, works as your $EDITOR, exports without a window, serves notes to agents and checks your setup. This page lists every subcommand and flag in 0.1.0.

Where it lives

The command ships inside the app at /Applications/Dewline.app/Contents/Helpers/dewline. The Homebrew cask links it onto your PATH. Without the cask, call it by that full path.

$ dewline --version
dewline 0.1.0

Every example below ran against the 0.1.0 build on 2 November 2026, in a scratch folder. Paths in the output show the home folder as /Users/you.

Commands

CommandWhat it does
openOpens files in Dewline at a line and column, starting the app if it isn't running.
notifyTells Dewline which file an agent's tool is changing. Agent hooks run it.
changesLists the agent changes you kept and reverted, oldest first.
captureAdds a dated entry to your inbox note.
exportWrites a Markdown file as HTML, PDF or DOCX.
mcpServes a folder's notes to an agent over MCP on stdio.
doctorChecks the app's version, the agent hooks and the companion tools.

dewline --help and dewline <command> --help print the same list and each command's flags.

dewline open

dewline open [--wait] <FILE[:LINE[:COLUMN]]>...

Opens each file in Dewline and brings the app forward. When the app isn't running, the command starts it, waits up to 10 seconds for it to listen, and gives it 10 seconds to show each file.

FILE[:LINE[:COLUMN]]
A file, with the caret at LINE and COLUMN when given. Both count from 1. A relative path starts at the current folder, and a leading ~ is your home folder. When a file exists under the whole argument, it opens as itself, so a colon in a file name stays part of the name.
--wait
Returns once every file's window has closed. Git and other tools that start an editor need this to know you are done.

The command checks every file before it asks the app for any, so one bad name opens nothing. It refuses a folder (is a folder; dewline open takes files), anything that isn't a regular file, and a path that isn't UTF-8.

# open a note with the caret on line 12, column 4
$ dewline open projects/launch-plan.md:12:4

# open two files and wait until both windows close
$ dewline open --wait plan.md notes.md

# after --, a name that starts with a dash is a file
$ dewline open -- -draft.md

Use it as your editor

Set VISUAL or EDITOR to dewline open --wait. Git reads them for commit messages and rebase lists. Claude Code reads $VISUAL, then $EDITOR, for ⌃G and plan approval, and waits for the command to exit. What you save there is your own write, not the agent's.

# ~/.zshrc or ~/.bashrc
export VISUAL="dewline open --wait"
export EDITOR="dewline open --wait"
# ~/.config/fish/config.fish
set -gx VISUAL "dewline open --wait"
set -gx EDITOR "dewline open --wait"

If Dewline quits before the window closes, the command fails with Dewline quit before the file closed.

dewline notify

dewline notify --hook <claude|codex|cursor>

Agent hooks run this command with the hook event's JSON on stdin. It sends Dewline the realpath of each file a tool names and BLAKE3 hashes of its bytes, never the content, so the change can carry the agent's name. You don't run it yourself. Agents and changes covers what it sends and how to install the hooks.

--hook <claude|codex|cursor>
Whose hook runs it. Required.

It never writes a file, never starts the app and never runs another program. It finishes within 2 seconds whatever stdin holds, and when Dewline isn't running it stops before reading stdin. It always exits 0, even on a bad flag, because Claude Code and Codex take a hook's exit code 2 as a refusal of the tool call.

dewline changes

dewline changes [--json] [--session <ID>] [--since <TIME>]

Lists each agent change you kept or reverted in Dewline, oldest first: the time in UTC, the decision, the agent and its session, and the file. An agent can run it before its next edit to see what you threw away.

--json
Prints a JSON array, one object per decision.
--session <ID>
Only this agent session's decisions.
--since <TIME>
Only decisions at or after this UTC time, in RFC 3339 or a prefix of it: 2026-10-30, 2026-10-30T18:00, 2026-10-30T18:00:00Z.
$ dewline changes
2026-11-02T17:42:10Z  kept      claude 9f2c51e0-demo  /Users/you/Notes/projects/launch-plan.md
2026-11-02T17:55:31Z  reverted  codex 019a3b7e-demo  /Users/you/Notes/journal/2026-11-02.md
2026-11-02T18:03:44Z  kept      claude 4d71a0c2-demo  /Users/you/Work/other-repo/README.md

$ dewline changes --since 2026-11-02T17:50
2026-11-02T17:55:31Z  reverted  codex 019a3b7e-demo  /Users/you/Notes/journal/2026-11-02.md
2026-11-02T18:03:44Z  kept      claude 4d71a0c2-demo  /Users/you/Work/other-repo/README.md
$ dewline changes --json --session 9f2c51e0-demo
[{"vendor":"claude","session":"9f2c51e0-demo","file":"/Users/you/Notes/projects/launch-plan.md","time":"2026-11-02T17:42:10Z","decision":"kept","excerpt_hash":"b8bd7e533ca4a32f8950b88300c840eb8b74fd14a30f4c54c916c7224b5e644a"}]

The JSON fields are vendor (the agent, such as claude or codex), session, file, time, decision (kept or reverted) and excerpt_hash, the BLAKE3 hash of the change's text. The log never holds the text itself. No decisions prints nothing and exits 0.

dewline capture

dewline capture [TEXT]...

Adds one dated entry to the end of your inbox note. The words become the entry; with no words, the command reads stdin. The inbox is ~/Documents/Dewline/Inbox.md unless you pick another file in Settings > Files > Inbox. The command makes the file and its folders when they are missing.

$ dewline capture Call the notary about the DMG
$ echo "- [ ] Check the appcast before tagging" | dewline capture
$ cat ~/Documents/Dewline/Inbox.md
2026-11-02 18:24 · cli
Call the notary about the DMG

2026-11-02 18:24 · cli
- [ ] Check the appcast before tagging

Each entry starts with the local time to the minute and its source: cli here, mcp from the MCP server, shortcuts from the Shortcuts action. The bytes already in the file stay as they are. The append is a compare-and-swap, so an open inbox window takes it as an outside change. Empty text adds nothing:

$ dewline capture "  "
dewline: /Users/you/Documents/Dewline/Inbox.md: there is nothing to capture

dewline export

dewline export <FILE> --to <html|pdf|docx> [-o <OUT>]
--to <html|pdf|docx>
The format. Required.
-o <OUT>
Where the export goes. By default it goes beside FILE with the format's extension.

The command writes HTML and DOCX itself, with no window, and inlines images from the file's folder. Diagrams and math keep their source. The HTML page uses the system fonts at a 42em measure, follows light and dark mode, and carries a Content Security Policy that loads nothing from the network. PDF needs the app, which owns the paged layout: the command hands the file to Dewline.

$ dewline export projects/launch-plan.md --to html
$ ls projects
launch-plan.html
launch-plan.md
$ dewline export reading.md --to docx -o ../reading.docx
$ file ../reading.docx
../reading.docx: Microsoft Word 2007+

An export never replaces its own source:

$ dewline export reading.md --to html -o reading.md
dewline: /Users/you/Notes/reading.md: the export would replace its own source

Export covers what each format keeps.

dewline mcp

dewline mcp <ROOT>

Serves the notes in ROOT to an agent over MCP, on stdin and stdout, until stdin closes. Agents start it; you add it to their config once. MCP server covers setup, tools and limits.

It refuses a folder that is your home folder or holds it, a folder inside ~/Library, and a folder that holds .ssh:

$ dewline mcp ~
dewline: /Users/you: the folder is your home folder or holds it
$ dewline mcp ~/Library/Notes
dewline: /Users/you/Library/Notes: the folder is inside ~/Library
$ dewline mcp ~/keys
dewline: /Users/you/keys: the folder holds .ssh

dewline doctor

dewline doctor [--install-hooks | --links <DIR>]

With no flag, it reports three things and changes nothing: whether the app matches this command, which agent hooks are in place, and which companion tools are on your PATH.

$ dewline doctor
Version: app and command are both 0.1.0

Agent hooks:
  Claude Code: installed in /Users/you/.claude/settings.json
  Codex: PostToolUse missing from /Users/you/.codex/hooks.json
  Cursor: preToolUse, postToolUse, stop missing from /Users/you/.cursor/hooks.json
  `dewline doctor --install-hooks` merges the missing ones in, asking first.

Companions:
  pandoc: /opt/homebrew/bin/pandoc
  typst: /opt/homebrew/bin/typst
  vale: not installed; brew install vale
  harper-ls: not installed; brew install harper

The version check reads the app that holds the command, or /Applications/Dewline.app when the command lives elsewhere. A mismatch says so and tells you to use the command inside the app. Settings > Agents runs the same check and shows each agent as Installed or Not installed.

--install-hooks
Merges the missing hooks into ~/.claude/settings.json, ~/.codex/hooks.json and ~/.cursor/hooks.json. For each file it prints the entries it would add and asks Merge them in? [y/N], so it needs a terminal. It keeps every other key and hook, copies the old file to <file>.dewline-backup-<seconds> first, and leaves a file alone if it changed after it was read. Agents and changes shows the hooks it adds.
--links <DIR>
Prints each broken relative link and CLAUDE.md @import in the Markdown files under DIR, and nothing else. A problem is no such file, imports a file that imports it or more than 5 imports deep. It skips hidden folders other than .claude, .cursor and .github, skips node_modules and target, and doesn't follow symlinked folders. It exits 1 when it finds any.
$ dewline doctor --links ~/Notes
/Users/you/Notes/reading.md:4: archive/2025.md (no such file)
dewline: 1 broken link

Exit codes

CodeMeaning
0Done. notify always exits 0.
1The command failed. Each line of the reason goes to stderr after dewline:. doctor --links also exits 1 when it finds a broken link.
2The arguments didn't parse: a missing file, an unknown flag or a value --to or --hook doesn't take.
 
$ dewline export reading.md --to rtf
error: invalid value 'rtf' for '--to <TO>'
  [possible values: html, pdf, docx]

For more information, try '--help'.
$ echo $?
2

Before it prints a path or a message from the app, the command replaces control characters with �, so a hostile file name can't drive your terminal.

Environment

VariableWhat the command does with it
HOMEFinds your home folder: the inbox, the decisions log, the app's socket, the agents' settings, and the folders mcp refuses.
PATHdoctor looks for pandoc, typst, vale and harper-ls on it.
DEWLINE_SOCKETTalks to the socket at this path instead of the app's. The command then never starts the app or brings it forward. Dewline's own tests use it.

The inbox location is not an environment variable. capture and mcp read the app's Settings > Files > Inbox choice from the DewlineInboxPath default in dev.arkwerx.dewline.

Files

The app's own folder is ~/Library/Application Support/dev.arkwerx.dewline, shortened here to …/dev.arkwerx.dewline.

~/Documents/Dewline/Inbox.md
capture and the MCP append_to_inbox tool append to it, unless Settings > Files > Inbox names another file.
…/dev.arkwerx.dewline/snapshots/decisions.jsonl
The app appends one line per Keep or Revert of an agent's change, readable only by you. changes and the MCP decisions tool read it.
…/dev.arkwerx.dewline/run/control.sock
open and notify talk to the app here. The command checks that the app on the other end runs as you.
~/.claude/settings.json, ~/.codex/hooks.json, ~/.cursor/hooks.json
doctor reads them. doctor --install-hooks writes them after you agree, with a backup beside each.
