Architecture

Dewline is a Swift and AppKit app over a Rust engine. The app draws the page and handles every keystroke; the engine reads and writes every byte on disk.

The split

The app is Swift 6 and AppKit. It owns the text view, layout, drawing, documents, windows and menus. It also owns the system text services: spell check, Writing Tools, dictation and the find bar.

The engine is Rust. It owns decoding, parsing, the change engine, snapshots, the path jail, rendering, collaboration and export. One engine serves the app, the Quick Look preview and the dewline command.

On the keystroke path the engine does one thing. It parses the edited window, at most 4 KB, with no locks held and no I/O.

Two other designs were ruled out. A pure Rust UI would lack VoiceOver for text, Writing Tools, the find bar, Services and spell check. A web view editor breaks the memory budget and limits Writing Tools to a panel. Record 0001 chose the stack.

Rules the code keeps

  • The Markdown text is the only model. Rendering changes attributes, never characters.
  • Opening a file never writes it. Bytes you did not edit never change.
  • Every write, from any writer, takes one path: detect, compare, snapshot, merge three ways, apply, then save only if the disk still matches.
  • Conflicts never enter the file.
  • Nothing restyles text or lands a change while an input method is composing.
  • Nothing touches the text view's layoutManager, which would switch it to TextKit 1.
  • After five seconds without input, nothing runs: no timers, no animation, no blinking caret.

How a save checks the disk

A save writes only if the file still holds the bytes it was based on, checked by BLAKE3 hash. The new bytes go to a hidden sibling with the file's mode, owner, flags and extended attributes. One rename then replaces the file.

A symlink, a file with other hard links or one with an access control list is written in place, through the descriptor that was hashed. If that write fails, the original bytes go back.

An outside change, disk to screen

When git, a sync app, a script or an agent writes an open note, the change takes the same eight steps.

  • The file is snapshotted before anything lands, and your unsaved typing before the merge.
  • While git holds index.lock or an agent's hooked call is open, the landing waits, 10 s at most.
  • A change carries a writer's name only when that writer's hooks report it (0007).

Collaboration

  • Mirror. One Loro document per shared note carries edits between Macs. The .md file on each Mac stays the source of truth.
  • Transport. iroh 1.3.0, peer to peer, with a relay when no direct path opens. The invite carries the host's address, so nothing is published.
  • Keys. Each message is sealed with XChaCha20-Poly1305 and signed with the sender's ed25519 key. Each approval or removal makes a new document key.
  • The seam. A collaborator's edit reaches the engine as one replace, outside your undo history, with the caret kept.

Not built yet: rejoining after a dropped connection, and edits over iroh-gossip's 1 MiB message size (0009).
