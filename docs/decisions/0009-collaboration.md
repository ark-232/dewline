# 0009: Live collaboration by invite link

Date: 2026-10-30. Builds D13 for M7; the external protocol review still gates release.

| Decision | Choice | Reopens if |
|---|---|---|
| Mirror | `core/crates/sync`: one Loro doc per shared file, one text container (`md`). The `.md` on each Mac stays the source of truth; Loro carries edits between Macs and nothing reads it back from disk. | Loro drops `fork_at` or UTF-16 positions |
| Seed | The host seeds a new Loro doc from the file's text as it is when Share is first pressed. Pre-share history never exists in Loro, so it can't leak; a guest gets a snapshot of the share's own history only. | |
| Transport | iroh 1.3.0 with relay fallback and no address lookup service: the link carries the host's address, so nothing is published to n0's DNS. A direct stream on ALPN `dewline/collab/0` carries joins, keys and removals; an iroh-gossip topic carries ops and cursors. | iroh changes its wire format before 1.0 of Dewline |
| Relay | `dewline_sync::RELAY`, one constant: n0's hosted relay (`use1-1.relay.n0.iroh.link`) during development. | the M7 entry decision below |
| Invite | `dewline://join?node=…&relay=…&addr=…&cap=…`: the host's node id, its relay, its direct addresses and a random 256-bit capability. The host spends a capability the first time anyone presents it, whatever the host then decides, so a link admits one join attempt. Each Copy Invite Link makes a new one. | |
| Join | The guest dials the host, presents the capability and a name (control characters dropped, 64 characters at most). The host approves or denies by that name. Approval sends the share's topic, the current document key, the members and a snapshot. | |
| Keys | Node keys are iroh's ed25519 keys. Each approval or removal makes a new 256-bit document key, sent over each member's direct stream with the members list. Gossip messages are XChaCha20-Poly1305 under the document key, with the sender's id as associated data, and signed by the sender's node key over the topic and the sealed bytes. A receiver drops anything not signed by a current member or not sealed under the current or previous key; the previous key covers ops in flight across a rotation, from members only. | |
| Removal | The host drops the node from the members, tells it it was removed, closes its stream and rotates the key. Its later ops fail the membership check, and it never gets the new key. A guest whose connection closes leaves the same way. | |
| Engine seam | Remote text arrives as one replace (`Share.pull`). `Engine::collaborate` takes it as `Origin::Collaborator { peer, name }`: it checks the edits fit the buffer, snapshots a buffer that differs from the base first (at most every 30 s, since collaborators type a keystroke at a time) and hands the edits back. The app holds them while an input method composes and applies them outside the undo history, keeping the caret's place. They reach only the shared document's buffer; the normal save writes the file. | |
| Local edits | Each edit to the text storage goes to the share as a UTF-16 replace. One made while collaborators' ops wait unpulled is made on a fork at the version the app shows, so Loro merges it as concurrent. Text typed during a composition goes out as one replace when it commits. | |
| Presence | Carets ride gossip as Loro cursors, so they survive concurrent edits, and reach the app as (peer, name, UTF-16 offset). They draw as 1.5 pt lines in the collaborator writer hue (OKLCH 0.56 0.20 350, 0.72 0.17 350 in dark) and do not blink; the name shows on hover. | |
| Guest's file | `~/Documents/Dewline Shared/<name>`, where the name is the host's file name reduced to its last component, without control characters, colons or leading dots, ending in `.md`. A file already there is never overwritten; the copy takes a number. | |
| Key storage | The login Keychain, generic passwords under service `dev.arkwerx.dewline.sync`: account `node` for this Mac's node key, `document <share id>` for each share's current key, `WhenUnlockedThisDeviceOnly`. | the gate below |

**Threat controls** (the Security model's "Stolen invite link or hostile collaborator" row). A reused link is refused because its capability is spent on first presentation. A stolen link that reaches the host first still needs the host to approve the name. Ops are signed by node keys and dropped unless a current member signed them, so a forged op or one from a removed node does nothing. The relay sees node ids, addresses and timing; QUIC encrypts every stream end to end, and gossip payloads are sealed under the document key on top of that. Inbound text touches only the shared document's buffer, and the only path a guest's Mac takes from the host is a file name jailed to `Dewline Shared`.

**Relay question.** n0's hosted relays cost nothing, are rate-limited and are run by a third party that sees the metadata above. Our own `iroh-relay` costs a small always-on server per region and keeps that metadata with us. The choice is made at M7 entry with its cost and lands as one edit to `RELAY`.

**Data-protection Keychain.** The data-protection Keychain needs the keychain-access-groups entitlement and a provisioning profile, which the M7 entry gate adds. Until then any app the user allows can read these items from the login Keychain.

**Dependencies.** Exact pins at least 14 days old on crates.io: iroh 1.3.0 (default features off: no UPnP port mapper, no metrics), iroh-gossip 0.101.0, loro 1.16.2, tokio 1.53.3, chacha20poly1305 0.11.0, data-encoding 2.11.1, getrandom 0.4.3, n0-future 0.3.2. Transitive versions were held to the same age, except four that fix advisories and are younger: rustls-webpki 0.103.16 (RUSTSEC-2026-0382), webpki-roots and webpki-root-certs 1.0.10 (RUSTSEC-2026-0381, RUSTSEC-2026-0383) and ctutils 0.4.4 (RUSTSEC-2026-0385). `core/deny.toml` records the new license exceptions and the unmaintained crates under Loro and iroh, each with its reason. The sync code links into `libdewline_ffi` for now; the lazily loaded dylib the plan names comes with the DMG budget check.

**Not yet built.** Rejoining after a dropped connection or a restart (a guest needs a new link today), catch-up beyond the guest asking the host whenever a gossip neighbor comes up, ops over the 1 MiB gossip limit, mapping the undo history through remote edits, and the app calling `collaborate` (documents open through the engine in M2's document lane; until then the app applies remote edits directly with the same IME and caret rules).
